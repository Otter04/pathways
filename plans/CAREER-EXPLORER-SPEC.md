# PATHWAYS 진로 탐색 개편 기준

작성일: 2026-11-12
대상: `docs/cs-career-roadmap-v2.html`
공개 주소: https://otter04.github.io/pathways/cs-career-roadmap-v2.html

## 1. 목적과 사용자

컴퓨터공학과 학생이 전공에서 연결되는 다양한 진로를 발견하고, 관심 분야 안에 어떤 세부 분야와 직업이 있는지 이해하도록 돕는다. 각 직업의 실제 업무와 결과물을 쉽게 비교하면서 관심 있는 선택지를 좁혀갈 수 있어야 한다.

주 사용자는 아직 희망 직업을 정하지 못했거나 직업 이름은 들어봤지만 하는 일의 차이를 모르는 학생이다. 전공 지식이나 직업 명칭을 이미 알고 있다고 가정하지 않는다.

사용자가 답을 얻어야 하는 질문:
- 컴퓨터공학을 공부하면 어떤 분야로 갈 수 있을까?
- 관심 있는 분야 안에는 어떤 세부 분야와 직업이 있을까?
- 각 직업은 무엇을 해결하고, 어떤 일을 하며, 무엇을 만들까?
- 비슷한 직업은 무엇이 다르고, 어떤 직업을 더 알아보고 싶을까?

## 2. 핵심 탐색 흐름

`관심 분야 선택 → 세부 분야 살펴보기 → 직업의 업무 이해 → 관심 저장·비교 → 필요할 때 학습 경로 보기`

첫 화면은 12개 분야를 소개한다. 64개 직업을 한 번에 펼쳐 놓지 않는다. 분야를 고르면 해당 분야의 설명, 세부 분야와 직업 카드가 나타난다. 직업 카드에서 이름·한 문장 설명·대표 업무·결과물을 확인하고 상세 화면으로 이동한다.

직무 이름을 이미 아는 사용자는 검색으로 바로 접근할 수 있다. 아직 분야를 모르는 사용자는 “화면과 서비스를 만들고 싶어요”처럼 쉬운 관심 문장으로 관련 분야를 살펴볼 수 있다. 관심 문장은 탐색 필터이며 적성 검사나 진로 추천 점수가 아니다.

## 3. 정보 구조와 화면

### A. 분야 탐색 홈
- 목적을 설명하는 짧은 제목과 `분야 → 세부 분야 → 직업` 흐름 안내.
- 만들기, 사람·서비스 이해, 데이터·AI, 안정적 운영·보호, 기기·연구 등의 관심 문장 필터.
- 12개 분야 카드: 분야명, 쉬운 설명, 세부 분야 미리보기, 직업 수, 진입 버튼.
- 직업명·업무·기술을 함께 찾는 검색. 검색 결과에는 소속 분야와 하는 일을 표시.
- 검색 결과 없음 상태와 초기화 동작.

### B. 선택한 분야
- 상단에 현재 위치와 전체 분야로 돌아가기.
- 분야의 핵심 역할을 쉬운 문장으로 설명.
- 세부 분야 탭: 전체 및 분야 안의 2~4개 묶음. 선택 상태는 주소에 포함하여 새로고침과 뒤로 가기에서 유지.
- 세부 분야별 설명과 소속 직업 카드.
- 직업 카드: 직업명, 쉬운 요약, 대표 업무, 대표 결과물, 상세 보기, 관심 저장, 비교에 담기.
- 관련 분야 연결을 제공하여 한 분야에서 탐색이 막히지 않게 한다.

### C. 직업 상세
- 전체 분야 / 선택한 분야 / 세부 분야 / 직업의 현재 위치.
- 직업명과 한 문장 역할 설명.
- 가장 먼저 실제 업무, 업무 결과물, 같은 분야에서 역할이 어떻게 다른지를 제시.
- 관심 저장과 비교를 주요 행동으로 둔다.
- 기존 역량·참고 출처·진입 안내·관련 직업·학습 경로는 이어지는 정보로 제공.
- 목표를 먼저 정해야만 내용을 볼 수 있는 흐름을 만들지 않는다.

### D. 관심 직업과 비교
- 관심 저장 목록을 별도 메뉴에서 열고 새로고침 후에도 유지.
- 사용자가 선택한 직업을 최대 3개까지 비교. 새 사용자의 비교 목록은 비워 둔다.
- 업무 목적 / 실제 업무 / 결과물 / 역량 / 학습 경로를 같은 기준으로 비교.
- 기존 사용자가 선택한 비교 목록과 목표·학습 기록을 보존.

## 4. 내용 원칙

- 기존 12개 분야와 64개 직업의 ID, 업무 설명, 출처를 유지한다.
- 새 세부 분야 묶음과 관심 문장은 탐색을 위한 편집상 분류다. 공식 직업 분류·유일한 진로 경로로 표현하지 않는다.
- 모든 직업은 기본 소속 세부 분야 하나를 갖고, 관련 직업·분야를 통해 다른 연결도 보여준다.
- 직업명에는 전문 직무 및 유사 직무를 묶은 항목이 포함되어 있음을 설명한다.
- 대표 업무와 준비를 위한 학습 제안을 구분한다.
- 기존 출처 확인일은 실제 재조사 없이 갱신하지 않는다. 이번 작업은 탐색 구조와 화면 개선이다.
- 취업 가능성·연봉·적합도 점수를 추정하지 않는다.

## 5. 디자인 기준

PATHWAYS의 짙은 초록색 브랜드를 유지하고, 밝은 미색 바탕과 넓은 여백으로 탐색 정보를 구분한다. 짙은 초록색은 주요 선택·이동, 옅은 초록색은 선택된 분야, 중립 회색은 보조 설명에 사용한다.

- 홈: 짧은 소개와 작은 경로 그림, 관심 문장, 분야 카드 순서. 카드에는 실제 설명을 넣는다.
- 데스크톱: 상단 전역 메뉴, 왼쪽 분야 목록, 오른쪽 현재 탐색 화면. 본문은 읽기 좋은 폭을 유지.
- 분야 카드: 데스크톱 최대 3열, 중간 화면 2열, 모바일 1열.
- 세부 분야는 이름만 나열하지 않고 무엇을 다루는지 한 문장으로 설명.
- 직업 카드는 이름보다 하는 일의 설명을 충분히 읽을 수 있게 구성.
- 장식용 사진 대신 작은 기호와 연결 구조를 사용. 복잡한 그래프 조작을 요구하지 않는다.
- 주요 본문은 14~16px 이상, 충분한 대비, 명확한 제목 계층, 44px 안팎의 터치 영역.
- 모바일은 고정 좌측 메뉴를 숨기고 전역 메뉴와 분야 선택을 본문에서 제공. 페이지 전체의 가로 넘침을 방지.
- 키보드 탐색, 초점 표시, 버튼 이름, 선택 상태, 결과 수 안내를 제공. 모션 감소 설정을 존중.

## 6. 구현·배포 범위

- 기존 GitHub 저장소 `Otter04/pathways`, `main /docs` 게시 방식과 주소를 유지.
- 단일 HTML에 들어 있던 로드맵 데이터·동작·스타일을 별도 원본으로 정리하고 생성기로 HTML을 재생성한다.
- 기존 `#/job/<id>`, `#/path/<track>/<role>`, `#/map/<track>` 링크를 유지한다.
- 기존 저장 키 `pathways-careers-v2`, 이전 기록 가져오기, 학습 체크·메모, 백업·복원을 유지한다.
- 채용 탐색 페이지와 공고 데이터, 3일 주기 갱신 예약은 이번 수정 대상에 포함하지 않는다.
- 추가 계정, 로그인, 유료 서비스 또는 서버를 만들지 않는다.
