# PATHWAYS 진로 탐색 개편 기준

작성일: 2026-11-12
대상: `docs/cs-career-roadmap-v2.html`
공개 주소: https://otter04.github.io/pathways/cs-career-roadmap-v2.html

## 1. 목적과 사용자

컴퓨터공학과 학생이 전공에서 연결되는 다양한 진로를 발견하고, 관심 분야 안에 어떤 세부 분야와 직업이 있는지 이해하도록 돕는다. 각 직업의 실제 업무와 결과물을 쉽게 비교하면서 관심 있는 선택지를 좁혀갈 수 있어야 한다.

주 사용자는 아직 희망 직업을 정하지 못했거나 직업 이름은 들어봤지만 하는 일의 차이를 모르는 학생이다. 전공 지식이나 직업 명칭을 이미 알고 있다고 가정하지 않는다.

사용자가 답을 얻어야 하는 질문:
- 컴퓨터공학을 공부하면 어떤 분야로 갈 수 있을까?
- 관심 있는 분야 안에는 어떤 세부 분야와 직업이 있을까?
- 각 직업은 무엇을 해결하고, 어떤 일을 하며, 무엇을 만들까?
- 비슷한 직업은 무엇이 다르고, 어떤 직업을 더 알아보고 싶을까?

## 2. 핵심 탐색 흐름

`관심 분야 선택 → 세부 분야 살펴보기 → 직업의 업무 이해 → 관심 저장·비교 → 필요할 때 학습 경로 보기`

첫 화면은 12개 분야를 소개한다. 64개 직업을 한 번에 펼쳐 놓지 않는다. 분야를 고르면 해당 분야의 설명, 세부 분야와 직업 카드가 나타난다. 직업 카드에서 이름·한 문장 설명·대표 업무·결과물을 확인하고 상세 화면으로 이동한다.

직무 이름을 이미 아는 사용자는 검색으로 바로 접근할 수 있다. 아직 분야를 모르는 사용자는 “화면과 서비스를 만들고 싶어요”처럼 쉬운 관심 문장으로 관련 분야를 살펴볼 수 있다. 관심 문장은 탐색 필터이며 적성 검사나 진로 추천 점수가 아니다.

## 3. 정보 구조와 화면

### A. 분야 탐색 홈
- 목적을 설명하는 짧은 제목과 `분야 → 세부 분야 → 직업` 흐름 안내.
- 만들기, 사람·서비스 이해, 데이터·AI, 안정적 운영·보호, 기기·연구 등의 관심 문장 필터.
- 12개 분야 카드: 분야명, 쉬운 설명, 세부 분야 미리보기, 직업 수, 진입 버튼.
- 직업명·업무·기술을 함께 찾는 검색. 검색 결과에는 소속 분야와 하는 일을 표시.
- 검색 결과 없음 상태와 초기화 동작.

### B. 선택한 분야
- 상단에 현재 위치와 전체 분야로 돌아가기.
- 분야의 핵심 역할을 쉬운 문장으로 설명.
- 세부 분야 탭: 전체 및 분야 안의 2~4개 묶음. 선택 상태는 주소에 포함하여 새로고침과 뒤로 가기에서 유지.
- 세부 분야별 설명과 소속 직업 카드.
- 직업 카드: 직업명, 쉬운 요약, 대표 업무, 대표 결과물, 상세 보기, 관심 저장, 비교에 담기.
- 관련 분야 연결을 제공하여 한 분야에서 탐색이 막히지 않게 한다.

### C. 직업 상세
- 전체 분야 / 선택한 분야 / 세부 분야 / 직업의 현재 위치.
- 직업명과 한 문장 역할 설명.
- 가장 먼저 실제 업무, 업무 결과물, 같은 분야에서 역할이 어떻게 다른지를 제시.
- 관심 저장과 비교를 주요 행동으로 둔다.
- 기존 역량·참고 출처·진입 안내·관련 직업·학습 경로는 이어지는 정보로 제공.
- 목표를 먼저 정해야만 내용을 볼 수 있는 흐름을 만들지 않는다.

### D. 관심 직업과 비교
- 관심 저장 목록을 별도 메뉴에서 열고 새로고침 후에도 유지.
- 사용자가 선택한 직업을 최대 3개까지 비교. 새 사용자의 비교 목록은 비워 둔다.
- 업무 목적 / 실제 업무 / 결과물 / 역량 / 학습 경로를 같은 기준으로 비교.
- 기존 사용자가 선택한 비교 목록과 목표·학습 기록을 보존.

## 4. 내용 원칙

- 기존 12개 분야와 64개 직업의 ID, 업무 설명, 출처를 유지한다.
- 새 세부 분야 묶음과 관심 문장은 탐색을 위한 편집상 분류다. 공식 직업 분류·유일한 진로 경로로 표현하지 않는다.
- 모든 직업은 기본 소속 세부 분야 하나를 갖고, 관련 직업·분야를 통해 다른 연결도 보여준다.
- 직업명에는 전문 직무 및 유사 직무를 묶은 항목이 포함되어 있음을 설명한다.
- 대표 업무와 준비를 위한 학습 제안을 구분한다.
- 기존 출처 확인일은 실제 재조사 없이 갱신하지 않는다. 이번 작업은 탐색 구조와 화면 개선이다.
- 취업 가능성·연봉·적합도 점수를 추정하지 않는다.

## 5. 디자인 기준

PATHWAYS의 짙은 초록색 브랜드를 유지하고, 밝은 미색 바탕과 넓은 여백으로 탐색 정보를 구분한다. 짙은 초록색은 주요 선택·이동, 옅은 초록색은 선택된 분야, 중립 회색은 보조 설명에 사용한다.

- 홈: 짧은 소개와 작은 경로 그림, 관심 문장, 분야 카드 순서. 카드에는 실제 설명을 넣는다.
- 데스크톱: 상단 전역 메뉴, 왼쪽 분야 목록, 오른쪽 현재 탐색 화면. 본문은 읽기 좋은 폭을 유지.
- 분야 카드: 데스크톱 최대 3열, 중간 화면 2열, 모바일 1열.
- 세부 분야는 이름만 나열하지 않고 무엇을 다루는지 한 문장으로 설명.
- 직업 카드는 이름보다 하는 일의 설명을 충분히 읽을 수 있게 구성.
- 장식용 사진 대신 작은 기호와 연결 구조를 사용. 복잡한 그래프 조작을 요구하지 않는다.
- 주요 본문은 14~16px 이상, 충분한 대비, 명확한 제목 계층, 44px 안팎의 터치 영역.
- 모바일은 고정 좌측 메뉴를 숨기고 전역 메뉴와 분야 선택을 본문에서 제공. 페이지 전체의 가로 넘침을 방지.
- 키보드 탐색, 초점 표시, 버튼 이름, 선택 상태, 결과 수 안내를 제공. 모션 감소 설정을 존중.

## 9. 두 번째 개편: 업무를 장면으로 이해하기

요청일: 2026-11-12. 이 절을 먼저 갱신한 뒤 사례·화면 작업을 시작한다. 앞선 완료 표시는 1차 개편의 검증 기록이며, 이번 범위의 완료 기준은 아래에 별도로 둔다.

### 목적

학생이 직업의 정의를 읽고도 “그래서 실제로 무엇을 하는가?”를 떠올리기 어려운 문제를 해결한다. 모든 64개 직업에 하나의 구체적인 업무 상황과 학생용 프로젝트를 제공한다. 사례를 읽으면 맡은 문제, 판단·행동 과정, 동료와의 협업, 만들어 내는 결과를 설명할 수 있어야 한다.

### 콘텐츠 기준

- 직업마다 **업무 사례 1개 + 학생용 프로젝트 1개**를 직접 작성한다. 제목만 바꾼 공통 문장을 반복하지 않는다.
- 업무 사례: 상황·요청 → 내가 하는 일 3단계 → 결과물의 구체적인 내용 → 함께 일하는 사람 → 잘 해결됐는지 확인할 기준.
- 업무 사례는 대표 업무를 바탕으로 구성한 **가상의 설명용 사례**다. 특정 회사의 실제 사건·성과·고객 사례로 표현하지 않는다. 화면과 결과물 예시에도 이 사실을 표시한다.
- 프로젝트: 작은 목표, 사용할 데이터·도구·환경, 첫 버전 범위, 진행 단계 3개, 제출할 결과물, 확인할 질문, 확장 아이디어.
- 프로젝트는 **학습용 제안**이며 입사 과제나 실무 자격 조건을 뜻하지 않는다. 예상 기간과 성과 수치를 임의로 약속하지 않는다.
- 학생이 혼자 또는 소규모 팀으로 시작할 수 있게 범위를 제한한다. 실제 고객·개인정보·운영 시스템 대신 가상 데이터, 로컬 환경, 공개 자료, 시뮬레이터를 활용한다. 보안 실습은 소유하거나 허가된 연습 환경으로 한정한다.
- 전문 용어는 가능한 쉬운 표현으로 바꾸며, 남겨야 하는 핵심 용어에는 짧은 풀이를 제공한다.
- 직업별 역할은 기존 출처와 공식 직업·기술 자료를 참고한다. 새로 확인한 자료의 확인일과 기존 자료의 확인일을 분리한다. 업무 사례와 프로젝트 자체는 편집한 교육 콘텐츠다.

### 디자인에 대한 판단과 수정 방향

현재 화면은 분야를 단계적으로 좁히기에는 적합하지만, 동일한 카드의 반복과 작은 설명 글씨, 추상적인 업무 항목 때문에 직업을 상상하는 데 한계가 있다. 학생 대상 사용성 조사 없이 “최선의 디자인”이라고 판단하지 않는다. 이번 방향은 사례 이해를 높이기 위한 개선안이며 실제 탐색에서 검증한다.

1. **직업 상세를 사례 중심으로:** 첫 화면에 직업의 역할과 대표 업무 상황을 보여주고, ‘업무 사례 / 학생 프로젝트 / 역할과 비교’ 바로가기를 제공한다.
2. **문제·행동·결과를 구분:** 상황은 색이 있는 짧은 안내, 행동은 번호가 붙은 읽기 쉬운 단계, 결과는 문서·화면에 들어갈 내용의 미리보기로 표현한다. 초록 브랜드와 미색 배경을 유지하되 문서 예시에는 푸른색, 프로젝트에는 따뜻한 색을 보조로 사용한다.
3. **진행 과정을 살펴보는 동작:** 업무 단계 선택 시 해당 단계의 설명과 산출물 예시가 바뀐다. 단계 버튼에는 선택 상태와 키보드 초점이 있고 모바일에서는 세로로 쌓인다. 교육 예시임을 항상 표시한다.
4. **탐색 카드에도 상황 예고:** 직업명·정의 아래에 ‘이런 문제를 다뤄요’와 사례 제목을 넣어 상세 화면에서 볼 내용을 예고한다. 검색은 사례·프로젝트 제목과 내용도 포함한다.
5. **모두 펼치지 않기:** 업무 사례와 프로젝트가 핵심 본문이 된다. 기존 업무 요약·역량·참고 출처는 이어지는 영역 또는 펼쳐보기로 제공하고, 관심 저장·비교·학습 기능을 유지한다.
6. **읽기 편한 크기:** 사례·프로젝트 본문 15~16px, 제목 24px 안팎, 충분한 대비와 문단 간격, 키보드 조작, 390px 모바일에서 잘리지 않는 구성.

### 2차 개편의 구현·검증 기록

- 64개 직업에 서로 다른 가상 업무 사례 64개와 학습 프로젝트 64개를 작성했다. 사례에는 총 192개 행동 단계와 단계별 결과물 내용이 있다.
- 프로젝트마다 목표·준비 자료·첫 버전 범위·3단계 진행·결과물·확인 질문·확장 방향을 제공한다. 필요한 용어를 별도 펼쳐보기로 설명한다.
- 상세 화면은 업무 사례 → 학생 프로젝트 → 역할 비교·보조 자료 순서로 바꿨다. 모든 단계는 버튼으로 선택할 수 있고 선택 상태·해당 결과물이 함께 바뀐다.
- 분석 사례에는 가상 인원 그래프, 기획·개발·보안·회로·테스트 사례 일부에는 구체적인 표 형태의 결과물 미리보기를 넣었다. 가상 수치와 예시임을 따로 표시했다.
- 직업 카드에 사례 제목을 표시하고, 사례·프로젝트 내용까지 검색한다. 직업 비교 표에도 업무 사례와 학생 프로젝트를 추가했다.
- 상세 화면의 비교 알림은 본문을 가리지 않도록 아래에 배치했다. 업무 단계는 초록, 결과물은 파랑, 학생 프로젝트는 따뜻한 미색으로 구분했다.
- 자동 검사: 전체 64개 화면 생성, 사례·프로젝트 고유성과 필수 항목, 192개 단계, 단계 선택의 잘못된 입력, 사례 내용 검색·결과 없음·초기화, 비교 표시, 기존·이전 학습 기록 호환성이 통과했다.
- 기존 채용 데이터 검증(공고 34개·기업 27개)과 기존 15개 검증도 통과했다. 채용 화면과 데이터는 수정하지 않았다.
- 브라우저 확인: 단계 변경, Enter 키 조작, 바로가기의 초점 이동, 프로젝트 확장 내용, 내용 검색, 관심 저장 후 새로고침, 비교 표의 사례·프로젝트 표시를 확인했다. 시험 중 추가한 관심·비교 항목은 원래 상태로 돌렸다.
- 1440px 데스크톱, 1024px 중간 화면, 390px 모바일에서 확인했다. 모바일에서는 개발·기획·보안·회로·연구·솔루션 등 6개 대표 직업의 전체 문서 가로 넘침이 없었다. 사례 본문은 모바일 15px 이상이다. 브라우저 오류 로그는 없었다.
- 이 검증은 화면·기능 확인이다. 실제 학생 대상 사용성 조사나 프로젝트 수행 결과는 아니며, 가장 좋은 디자인임을 입증하지 않는다.
