# PATHWAYS — 온라인 자동 반영 연결판

## 현재 상태 — 2026-11-12

사이트 코드와 최초 배포 스크립트가 준비되었고, 기존 ChatGPT의 3일 주기 예약은 `Otter04/pathways`의 공개 데이터를 갱신하도록 수정되었습니다. **실제 저장소 생성·GitHub Pages 활성화·공개 웹 게시 확인은 아직 완료되지 않았습니다.** 현재 연결 도구에는 새 저장소 생성과 Pages 설정을 실행하는 기능이 없어, 최초 연결은 사용자 기기에서 한 번 실행해야 합니다.

기존의 다른 GitHub 저장소는 수정하지 않았습니다. 2026-11-12 조사로 기업 공고 2건·플랫폼 공고 1건을 추가하고 기한이 지난 3건을 참고용으로 전환했습니다. 모든 기존 공고를 재확인한 것은 아닙니다. 변경 근거는 sources/REFRESH-2026-11-12.md를 확인하세요.

## 최초 연결: macOS

1. ZIP을 다운로드 폴더에 압축 해제합니다. `PATHWAYS-refresh-2026-11-12` 폴더가 생깁니다.
2. 터미널에서 실행합니다.

```bash
bash "$HOME/Downloads/PATHWAYS-refresh-2026-11-12/setup.sh"
```

다른 폴더에 풀었다면 `bash ` 뒤에 Finder의 `setup.sh` 파일을 터미널로 끌어놓아 경로를 입력한 후 Enter를 누르면 됩니다.

3. 스크립트 안내에 따라 GitHub의 **Otter04** 계정으로 로그인하고, 새 **공개 저장소** 생성과 사이트 공개를 승인합니다. GitHub CLI가 없다면 Homebrew 설치 여부를 확인한 뒤 설치 승인을 묻습니다. Homebrew가 없다면 GitHub CLI 설치가 먼저 필요합니다. Git도 필요하며, macOS가 Command Line Tools 설치를 요구하면 이를 완료한 뒤 다시 실행합니다.

로그인·토큰 입력은 GitHub의 공식 인증 화면에서만 진행합니다. 비밀번호나 토큰을 채팅에 보내지 마세요.

스크립트가 하는 일:
- **Otter04/pathways**만 생성합니다. 다른 저장소는 사용하지 않습니다.
- 공개 사이트 코드와 공고 요약·출처만 업로드합니다. 개인 기록 백업 파일은 업로드하지 않습니다.
- GitHub Pages의 게시 위치를 **main 브랜치의 /docs**로 설정합니다.
- Pages가 실제 제공하는 JSON과 저장소 데이터가 일치하는지 확인합니다.
- 게시 확인 성공 시 실제 사이트 주소를 출력합니다. 실패/대기일 때는 그 상태를 구분하여 출력합니다.

같은 이름의 저장소가 이미 있는데 이 패키지의 프로젝트 표식과 다르면, 덮어쓰지 않고 중지합니다. 이 패키지로 이미 생성한 저장소라면 더 최신인 공고 데이터를 업로드한 옛 패키지로 되돌리지 않습니다.

## 연결된 GitHub 앱의 접근 범위

ChatGPT에서 연결한 GitHub 앱이 새 **pathways** 저장소를 읽고 쓸 수 있어야 예약 작업이 데이터를 갱신할 수 있습니다. 앱 설치가 **선택한 저장소만** 대상으로 되어 있다면 새 저장소를 접근 대상에 추가하세요. 기존 앱 연결을 해제하거나 다른 저장소의 권한을 넓힐 필요는 없습니다. 접근에 실패한 실행은 온라인 반영 완료라고 보고하지 않도록 설정했습니다.

## 연결 완료 뒤 동작

```text
기존 ChatGPT 예약: 3일마다 공개 공고 원문 재확인
  → 요구사항·출처·마감·중복·데이터 구조 검증
  → GitHub main의 docs/jobs-data.json 갱신
  → GitHub Pages가 변경 게시
  → 같은 웹주소에서 새 데이터 표시
```

브라우저는 접속 시와 화면이 보이는 동안 5분마다 같은 서버의 `jobs-data.json`을 조회합니다. **5분은 화면 데이터 재조회 간격이고, 외부 채용공고 수집은 기존 3일 주기 예약입니다.** 별도의 서버 크롤러나 GitHub cron을 중복 생성하지 않았습니다. 최초 연결 후 정기 갱신을 위해 Mac을 계속 켜놓을 필요는 없습니다. 다만 ChatGPT 예약과 GitHub 앱 연결·쓰기 권한이 유지되어야 합니다.

GitHub의 게시 처리나 캐시 때문에 저장소 수정 즉시 화면이 바뀐다고 보장하지 않습니다. 예약 작업은 공개된 데이터 버전까지 확인하도록 설정했으며, 미확인 시 게시 대기로 보고합니다.

## 데이터 안전성과 화면 상태

- 접속 실패 또는 잘못된 JSON이면 정상 데이터를 유지합니다. 처음부터 서버를 읽지 못하면 HTML에 포함된 초기 스냅샷을 표시하고 실패 상태를 알립니다.
- `로컬 파일 · 온라인 자동 반영 미연결`은 파일을 직접 연 상태입니다. 자동 반영은 최초 배포한 웹주소에서 사용합니다.
- `온라인 데이터 연결됨`은 서버 JSON을 읽었다는 의미입니다. 모든 공고가 현재 모집 중이거나 최신 검증을 통과했다는 보장은 아닙니다.
- 서버 조회 시각과 공고의 원문 확인일은 별도로 표시합니다.
- 기업 공고 / 플랫폼 공고 / 기업 채용관 / 저장한 공고 및 로드맵 연결을 유지합니다.
- 메모 작성 중에는 새 데이터로 화면을 덮어쓰지 않습니다. 필수요건의 순서가 바뀌면 같은 문구에만 체크를 유지합니다.
- 개인 메모·북마크·지원 상태는 브라우저에만 저장하고 GitHub로 보내지 않습니다.
- 공고 데이터에는 HTTPS 출처, 고유 ID, 직무·기업 연결과 크기 검사를 적용합니다. 개인 기록용 최상위 필드는 공개 데이터로 허용하지 않습니다.

## 이전 기록 이전

기존 로컬 사이트에서 **내 기록 백업**으로 JSON을 저장한 다음, 배포된 웹사이트의 **출처·업데이트 기준 → 기록 복원**으로 불러오세요. 파일 주소와 웹사이트 주소의 저장소는 다르므로 자동 이전을 전제로 하지 않습니다. 개인 기록 JSON은 공개 GitHub 저장소에 넣지 마세요.

## 파일과 유지보수

```text
pathways-project.json          프로젝트 식별 표식 / 게시 경로
setup.sh                       최초 1회 저장소·Pages 설정
README.md                      현재 안내
sources/                       이전 버전의 원문 출처·범위 기록
src/app.js                     기존 탐색·메모·비교 화면
src/live.js                    온라인 데이터 조회·실패 처리
src/validate-data.js            브라우저와 Node 공통 검증
src/styles.css                 기존 디자인 + 연결 상태 표시
validate_data.js               공개 데이터 검증 실행기
build_site.py                  최신 데이터로 HTML 스냅샷 재생성
test_live.js                  네트워크 모의 응답을 이용하는 단위 검증
docs/index.html               온라인 채용 탐색 첫 페이지
docs/pathways-jobs.html        같은 내용의 페이지
docs/jobs-data.json            유일한 공고 데이터 정본
docs/cs-career-roadmap-v2.html 기존 진로 로드맵 (내용 유지)
docs/.nojekyll                 정적 파일 게시 표시
```

소스를 수정할 때:

```bash
node validate_data.js
python3 build_site.py
node test_live.js
```

원문을 확인하지 않고 `verifiedAt`, `updatedAt`, `platformUpdatedAt`만 바꾸지 마세요. `publication.builtAt`은 파일 생성 시점이지 원문 확인일이 아닙니다. `sources/README.md` 등은 이전 버전 기록이며, 현재 운영 방식은 이 문서를 따릅니다.

## 확인한 범위와 남은 검증

공개 데이터 검증, 동일 출처 조회 구성, 새 데이터 적용, 메모/북마크 보존, 요건 재정렬, 입력 중 교체 지연, 오류 시 데이터 보존, 위험 링크/중복 ID/잘못된 참조 차단, 5분 조회 간격, 배포 HTML 구문 등 **15개 단위 검증을 통과**했습니다. 브라우저에 생성 HTML 자체를 렌더링하여 시작 화면과 390px 모바일 가로 넘침이 없는 것을 확인했습니다.

이 환경에서 로컬 HTTP 주소를 여는 브라우저 테스트는 정책 제한으로 실행하지 못했습니다. 따라서 네트워크 변경 테스트는 모의 응답 기반이고, 실제 GitHub 인증·새 저장소 생성·공개 Pages 배포 전체 과정은 아직 검증 전입니다. 최초 실행 스크립트도 구문 검사까지만 완료했으며 사용자 계정에서 실행하지 않았습니다.
